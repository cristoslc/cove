# Cove Data Inventory

This is the **complete enumeration of every piece of state Cove reads, writes,
or holds** — CA keys, service databases, admin credentials, API keys, seed
data, caches, and system config. It is organized by the **kind of state**, not
by filesystem location, so nothing hides inside a folder listing.

## How to read this

Each item is classified on the dimensions the governance policy will need:

- **SoT (source of truth):** who is authoritative for this value?
  - `wheel` — shipped in the `cove` tool, regenerable
  - `user-config` — operator-owned identity/preference/machine fact
  - `service-state` — lives in a running service's storage (DB, vault)
  - `external` — owned outside Cove (1Password, cloud)
  - `derived` — synthesized from other items (regenerable)
- **Durable:** must survive reinstall, upgrade, and machine transfer, or is it
  regenerable?
- **Backed up:** is it captured by the backup tool (assume Documents/ is
  covered by backrest/restic, per operator; other locations may or may not be)?
- **Regenerable:** if lost, can Cove recreate it without data loss?

## Cross-cutting findings

1. **Two irreplaceable secrets are in locations Cove deletes or doesn't back
   up:** the root CA private key (`~/.config/cove/pki/`) and the gitignored
   credential seeds (`compose/seeds/*.yaml`) both live outside
   `~/Documents/cove-data/` — so restic (backing up Documents/) does **not**
   capture them, and the seeds additionally sit inside the rmtree'd `compose/`.

2. **Admin identity has up to 4 co-existing copies that can diverge:** 1Password
   (canonical) → Vault KV cache → compose `.env` → service DB row. We watched
   this collision live with Speedtest. Precedence is undefined.

3. **`compose/` is a mixed tree:** wheel content + durable artifacts (`.env`,
   `certs/`, gitignored seeds). `extract_resources()` rmtree's the whole tree,
   so every reinstall wipes durable user-config and secrets. The CA escaped only
   because it lives in `pki/`, outside the tree.

4. **Orphaned state:** `Private/MinIO <host> Root` credential has no deployed
   service; several legacy signing keys (`cove_signing`, per-project `*_signing`)
   predate or duplicate `forgejo_signing`. Not harmful, but they are state to
   inventory and decide on.

5. **Version marker is unreliable** (`VERSION` = 0.1.0 vs actual 0.4.1).

## Findings

1. **blocking — compose/nginx/config.html.j2:31** — The documented download command `curl -o cove-root-ca.pem https://ca.cove/config/ca` fails in the exact scenario it is written for. Two problems: (a) `ca.cove` is a 301 redirect to `https://git.cove/config/ca` (default.conf.j2:91), so without `-L` curl saves an empty body to `cove-root-ca.pem`; (b) on a machine that has not yet trusted the Cove CA, plain curl fails TLS verification (`unable to verify`/self-signed error), which is precisely the situation of a Node client that needs the cert. Fix: `curl -kL -o cove-root-ca.pem https://ca.cove/config/ca`. (The `-k` chicken-and-egg originates in the plan §1, not the implementation — but it ships on the rendered page, so it should be fixed before merge.)

2. **minor — compose/nginx/config.html.j2:38** — The launchctl caveat says durable per-app env belongs in "launchd plist / systemd unit / Electron main". Setting `NODE_EXTRA_CA_CERTS` inside Electron's main process is unreliable: Chromium's network stack (renderer fetches, `net` module) does not honor it, and Node reads the variable during bootstrap before user code runs. For Electron the env var must be set before app launch (shell profile, wrapper script, or packaged plist/EnvVar), not in main. Reword to e.g. "the environment the app is launched from (launchd plist, systemd unit, shell profile / wrapper)". The `launchctl setenv` non-durability and per-machine claims themselves are accurate.

3. **nit — compose/nginx/config.html.j2:28** — `~/Documents/cove-data/certs/rootCA.pem` is the path on the Cove host machine, not the client reading the page. Tilde expansion in `export VAR=~/...` works in bash/zsh, but a client machine won't have this path. The next paragraph ("If the file is not on this machine…") partially covers it; consider "on the machine running Cove" to be explicit.

4. **nit — docs/test-coverage-matrix.yaml:270-274** — New matrix row marks `sad: skip`, but the presence-assertion test (`test_config_html_documents_node_ca_trust`) does exercise the sad direction (missing section/fragment fails loudly). `happy: executable, sad: executable` would be the honest row.
